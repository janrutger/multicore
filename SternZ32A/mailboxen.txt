
De CIU wordt uitgebreid met een FiFo Mailbox

Iedere CPU/Rcontext kan, via de CIU, een bericht sturen naar een connected 
de ontvanger heeft een read en een write pointer
de ontvanger kan de berichten lezen vanuit de mail-loop en vanuit locale contexten
de enveloppen kunnen meerdere waardes bevatten, en hebben afzender CPIid, mesg-size, status als header

onafhankelijk van de bericht omvang kan de FiFo mailbox 512 berichten bevatten.
wanneer er niet snel genoeg gelezen wordt, loopt deze FiFo vol, in dat geval een harde exit
Abandoned slots leveren een read-write pointer collission, bij iedere read-write collision dezelfe harde exit

versturen van een bericht

msg_start Rx Ry 
    - Rx is de remote CPU 
    - Ry is de size van het bericht en wordt de actuele write pointer
    mesg_start vraagt aan zijn locale CIU of CPU Rx bekend is, nee, dan harde fout 
    de locale CIU vraagt aan Rx een write-pointer,
    de remote CIU ziet de vraag, reserveerd het slot (afzender en size, values) set de status op WRITING en retouneert de write pointer
    en verhoogt de write_pointer voor de volgende msg_start
    de locale CIU maakt een tijdelijk slotID, (slotID, linkID, write-pointer) en retouneert het slotID naar Ry

msg_write Ry Rx
    - Ry is tijdelijk slotID
    - Rx is de value
    msg_write zegt tegen de locale CIU, stuur Rx naar slot Ry
    de locale CIU kijkt of het een geldig slotID is, nee, dan cpustatus FALSE
    de locale CIU stuurt Rx write-pointer naar de andere zijde van het linkID
    De remote CIU ontvangt value en writepointer, controleeert of de status writing is, nee, dan cpustatus FALSE
    en schrijft de value naar de envelop

    Er moeten size maal msg_write gedaan worden

msg_done Ry
    - Ry is tijdelijk slotID
    msg_done is einde bericht, het slot ID in Ry wordt naar de locale CIU gestuurd
    De locale CIU ziet het bericht en informeert de remote CIU
    de remote CIU zet de berichten status op VALID
    de locale CIU ruimt zijn tijdelijke slotID op



Lezen van een bericht (Read API)
msg_open Rx
    Rx ontvangt het gegenereerde read_slotID.
    msg_open vraagt aan de lokale CIU of er op de actuele read_pointer een bericht klaarstaat met de status VALID.
    Indien VALID:
        De lokale CIU reserveert het bericht voor de lezer en veranderd de status direct naar READING (voorkomt dat andere contexten op dezelfde CPU hetzelfde bericht tegelijkertijd openen).
        De lokale CIU genereert een tijdelijk read_slotID (read_slotID, read_pointer, data_offset) en retourneert dit in register Rx.
        De berichten status wordt Reading en de readpointer wordt verplaatst
        cpustatus wordt ingesteld op TRUE.
    Indien GEEN VALID bericht (FiFo leeg of bericht nog in WRITING):
        Er wordt geen slot geopend; cpustatus wordt ingesteld op FALSE.

msg_probe Ry Rx
    Ry is het actieve read_slotID.
    Rx is het bestemmingsregister voor de opgevraagde header-informatie.
    msg_probe leest de metadata uit de header van het geopende slot.

    msg_probe levert in Rx de berichtgrootte (msg_size) op. Dit stelt de lezer in staat om te bepalen hoeveel msg_read-acties er moeten volgen.

msg_read Ry Rx
    Ry is het actieve read_slotID.
    Rx is het bestemmingsregister waarin de uitgelezen waarde wordt opgeslagen.
    De lokale CIU controleert of Ry een geldig read_slotID is met de status READING. Zo niet: cpustatus = FALSE.
    De CIU leest het volgende datawoord uit de envelop op de huidige data_offset, slaat dit via een uCore-allocatie op in register Rx, en verhoogt de interne data_offset voor dit read_slotID.

    Er moeten exact msg_size maal msg_read worden uitgevoerd.

msg_close Ry
    Ry is het actieve read_slotID.
    msg_close geeft aan dat het bericht volledig is verwerkt.
    De lokale CIU zet de status van het betreffende FiFo-slot op FREE / EMPTY.

    Het tijdelijke read_slotID in Ry wordt opgeruimd.




Een aangepast programma model voor het mandelbrot script

In deze versie worden twee workers gestart (RBOOT) op een eigen CPU
en de workers besteden het rekenwerk uit via (R)CONTEXTEN

de dimensie zijn 200x200 dus totaal moeten er 40.000 pixels uitgerekend en geplot worden
De ene worker gaat de bovenste helft van het scherm uitrekenen 1 .. 20.000
De andere worker de onderste helft 20.001 40.000

naast de gebruikelijke initialisatie van het grafische scherm en andere zaken
reserveert CPU0 4 adressen in shared memory en vult deze met 0, 0, 0, 20.000
Waarbij de tweede 0 en 20.000 de start posities van de WORKERs zijn

en start beide CPU workers (RBOOT)

daarna start CPU0 een luister-loop en verwacht 40.000 berichten
en verwacht berichten op de MSG* queue met de TAG result
en print deze pixels bij binnenkomst

als er 40.000 result berichten zijn ontvangen springt CPU0 uit de loop en HALT

als de worker CPU start (CPU1/CPU3) kijkt hij naar de eerste waarde in shared memory
Wanneer dit een 0 is, schrijft hij zijn eigen CPUID naar deze positie

daarna leest hij weer de eerste waarde en als deze gelijk is aan zijn CPUID leest hij de startwaarde uit positie twee
Als de eerste waarde niet gelijk is aan zijn eigen CPUID, dan was de andere CPU eerder, en leest positie 3
en cotroleerd weer of deze 0 is, schrijft zijn CPUID, leest zijn CPUID en begint met start positie van adres 4

De worker CPU gaat nu 20.000 keer een RCONTEXT starten en controleren of er een result bericht is terug gestuurd vanuit een context
zodra de worker CPU een result bericht heeft onvangen stuurt hij deze direct door naar zijn parent CPU0 die de pixel plot
als er noggeen reuslt bericht klaar staat, start de worker de volgende RCONTEXT.
Als alle 20.000 contexten gestart zijn, wacht de worker CPU tot alle berichten ontvangen zijn en SUSPEND.


De RCONTEXTEN, gestart door de worker CPU, berekenen op hun beurt de pixel uit
zenden een TAG=result bericht naar de parent worker CPU en eindigen met AUTOCLOSE



MAP {
    MEMORY {
        PROGRAM 1024
        SHARED  1024
        PRIVATE 512
    }
    START main

    ; === CONSTANTEN & TAGS ===
    CONST IMG_WIDTH 200         ; 200 pixels breed
    CONST IMG_HEIGHT 200        ; 200 pixels hoog
    CONST WORKER_PIXELS 20000   ; 20.000 pixels per worker

    CONST TAG_RESULT 100        ; Berichten-TAG "result" (Pixel data)
    CONST TAG_DONE   999        ; Berichten-TAG "done" (Worker klaar signaal)

    CONST MAX_ITER 32           ; Maximale Mandelbrot iteraties

    ; Fixed-Point Schaal (Q1000: 1000 = 1.000)
    CONST FP_SCALE 1000
    CONST FP_HALF 500
    CONST BAILOUT 4000          ; Ontsnappingsgrens |z|^2 > 4.0

    ; I/O Poorten voor GraphicalDisplay
    IO DEV 0
    IO VAL 1
    IO X_POS 2
    IO Y_POS 3
    IO CMD 5

    CONST GRAPH_DEV 2
    CONST PLOT_CMD 2

    ; === MACRO'S ===
    MACRO fmul_round(Rx, Ry, scale_val, half_val) {
        MUL Rx, Ry
        ADDI Rx, half_val
        DIVI Rx, scale_val
    }
}

PROGRAM {

; ==========================================================
; DOMEIN 1: CPU 0 (MASTER COORDINATOR & DISPLAY PLOTTER)
; Bootst Workers en sluit af zodra beide Workers TAG_DONE (999) sturen
; ==========================================================
main:
    0 -> A
    0 -> B
    0 -> C
    0 -> K
    0 -> L
    0 -> M                      ; Register M = Aantal voltooide Workers (0..2)
    0 -> X
    0 -> Y
    0 -> Z

    ; 1. Initialiseer GraphicalDisplay bus
    GRAPH_DEV -> A
    OUT A DEV

    ; 2. Boot Worker 1 (Link 0) voor Bovenste Helft
    0 -> A
    RBOOT A WORKER_TOP_ENTRY

    ; 3. Boot Worker 2 (Link 3) voor Onderste Helft
    3 -> A
    RBOOT A WORKER_BOTTOM_ENTRY

; --- MASTER LISTEN LOOP ---
MASTER_LISTEN_LOOP:
    ; A. Luister naar binnenkomende pixels (TAG 100)
    100 -> B
    READ B (A, X, Y) {
        MAX_ITER -> Z
        IF (A == Z) TRUE { 
            0 -> A
        }
        IF (A == Z) FALSE {
            MULI A 7
        }
        OUT A VAL

        X -> A
        MULI A 2
        OUT A X_POS

        Y -> A
        MULI A 2
        OUT A Y_POS

        PLOT_CMD -> A
        OUT A CMD
        IOSYNC
    }

    ; B. Luister naar Worker Completion Signalen (TAG 999)
    999 -> B
    READ B () {
        INC M                   ; Worker is klaar! M++
    }

    ; C. Check of beide Workers (2) hun DONE signaal hebben gestuurd
    2 -> K
    IF (M == K) TRUE {
        JMP MASTER_DONE
    }

    JMP MASTER_LISTEN_LOOP

MASTER_DONE:
    HALT


; ==========================================================
; DOMEIN 2 & 3: WORKER CPU'S (CPU 1 & CPU 4)
; ==========================================================
WORKER_TOP_ENTRY:
    0 -> L                      ; Start-pixel index = 0 (bovenste helft)
    JMP WORKER_START_JOB

WORKER_BOTTOM_ENTRY:
    20000 -> L                  ; Start-pixel index = 20000 (onderste helft)
    JMP WORKER_START_JOB

WORKER_START_JOB:
    0 -> A
    0 -> X
    0 -> Y
    0 -> M                      ; Register M = spawn_count = 0
    0 -> Z                      ; Register Z = recv_count = 0
    0 -> K                      ; Register K = drain_timeout_counter = 0

; --- DISPATCH & FORWARD LUS (20.000 TAKEN) ---
WORKER_SPAWN_LOOP:
    WORKER_PIXELS -> C          ; C = 20000
    IF (M == C) TRUE {
        JMP WORKER_DRAIN_LOOP   ; Alle 20.000 contexten gestart
    }

    L -> A
    RCONTEXT A MANDEL_CALC      ; Upstream taakinjectie naar uCore
    SUCCES spawn_ok

    JMP CHECK_INCOMING_MSG

spawn_ok:
    INC L
    INC M

CHECK_INCOMING_MSG:
    100 -> B                    ; TAG_RESULT = 100
    READ B (A, X, Y) {
        100 -> B
        WRITE B (A, X, Y)       ; Stuur DIRECT door naar Parent CPU 0
        INC Z                   ; recv_count++
    }

    JMP WORKER_SPAWN_LOOP

; --- DRAIN LUS: Wacht tot resultaten doorgestuurd zijn (met Safety Timeout) ---
WORKER_DRAIN_LOOP:
    WORKER_PIXELS -> C          ; C = 20000
    IF (Z == C) TRUE {
        JMP WORKER_FINISH
    }

    ; Safety Timeout: als de worker 10.000 keer niks meer ontvangt, sluit af
    10000 -> C
    IF (K == C) TRUE {
        JMP WORKER_FINISH
    }

    100 -> B                    ; TAG_RESULT = 100
    READ B (A, X, Y) {
        100 -> B
        WRITE B (A, X, Y)
        INC Z
        0 -> K                  ; Reset timeout teller bij ontvangen bericht
    }

    INC K                       ; Geen bericht ontvangen? Increment timeout teller
    JMP WORKER_DRAIN_LOOP

WORKER_FINISH:
    ; Stuur TAG_DONE (999) signaal zonder payload naar Parent CPU 0
    999 -> B
    WRITE B ()
    SUSPEND


; ==========================================================
; DOMEIN 4: uCore SUB-CONTEXT (PIXEL CALCULATION ENGINE)
; ==========================================================
MANDEL_CALC:
    0 -> I
    0 -> B
    0 -> C
    0 -> K
    0 -> L
    0 -> M
    0 -> X
    0 -> Y 
    0 -> Z 

    IMG_WIDTH -> Z              ; Z = 200
    
    A -> C
    MOD C Z

    A -> K
    DIV K Z

    C -> X
    K -> Y

    C -> A
    MULI A 14
    SUBI A 2000
    A -> C

    K -> A
    MULI A 14
    SUBI A 1400
    A -> K

    0 -> L
    0 -> M
    0 -> Z

MANDEL_CORE_LOOP:
    L -> A
    fmul_round(A, L, FP_SCALE, FP_HALF)

    M -> B
    fmul_round(B, M, FP_SCALE, FP_HALF)

    A -> I
    ADD I B

    SUB A B
    ADD A C

    BAILOUT -> B
    IF (I > B) TRUE {
        JMP CALC_FINISHED
    }

    L -> I
    fmul_round(I, M, FP_SCALE, FP_HALF)
    MULI I 2
    ADD I K

    A -> L
    I -> M

    INC Z
    MAX_ITER -> B
    IF (Z == B) TRUE {
        JMP CALC_FINISHED
    }

    JMP MANDEL_CORE_LOOP

CALC_FINISHED:
    100 -> B
    WRITE B (Z, X, Y)
    AUTOCLOSE
}
